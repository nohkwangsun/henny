# 헨니 체크 (Henny Check)

**작업자가 오늘 할 일을 스스로 체크**하고,
**관리자가 전체 현황을 한눈에 보는** 가벼운 안드로이드 앱입니다.

앱은 하나지만 첫 실행 때 역할을 고릅니다.

| 역할 | 화면 |
|---|---|
| **작업자 기기** | 오늘 작업 목록 하나. 켜기 → 누르기 → 끝. |
| **관리자 기기** | 오늘 현황 / 통계 / 작업 관리 / 설정 4개 탭. |

---

## 1. APK 받기

설치 방법을 고르는 중이라면 **[INSTALL.md](INSTALL.md)** 를 보세요 — 사이드로딩 권한이 실제로
어떤 것인지, 스토어로 가면 무엇이 달라지는지 정리해 두었습니다.
플레이스토어 출시 절차는 **[PLAY_STORE.md](PLAY_STORE.md)** 에 있습니다. 아래는 사이드로딩 설명입니다.

이 저장소는 코드만 들어 있고, 설치 파일은 GitHub Actions가 만들어 줍니다.

1. GitHub 저장소 → **Actions** 탭 → **Build APK** 워크플로
2. 가장 최근 성공한 실행을 클릭
3. 아래쪽 **Artifacts → henny-apk** 를 내려받기
4. 압축 안의 `.apk` 를 작업자 기기와 관리자 기기에 각각 보내서 설치

설치할 때 "이 출처의 앱 설치 허용"을 한 번 켜 줘야 합니다
(설정 → 앱 → 특별한 앱 접근 → 알 수 없는 앱 설치).

> **서명 키를 등록하기 전에는 일회용 키로 서명한 시험용 APK만 만들어집니다.**
> 빌드마다 서명이 달라 덮어 설치가 안 되고, Play용 AAB는 일부러 만들지 않습니다. 계속 쓸 앱이라면
> [PLAY_STORE.md 1단계](PLAY_STORE.md#1-업로드-키-만들기-필수-제일-먼저)대로 키를 한 번 만들어
> GitHub Secrets에 넣으세요. 그 뒤로는 서명된 APK와 Play용 AAB가 함께 만들어지고,
> 덮어 설치해도 데이터가 유지됩니다.

## 2. 처음 설정하기 (5분)

### 관리자 기기

1. 앱 실행 → **관리자 기기예요**
2. 작업자를 한 명씩 추가
3. 저장소 선택 화면에서 **Firebase 데이터베이스 주소** 입력 → **연결하고 시작**
   - 주소 만드는 법은 아래 3번 참고 (구글 계정만 있으면 5분)
   - 지금 건너뛰고 나중에 설정 탭에서 해도 됩니다
4. **설정 탭 → 작업자 → 연결 코드** 를 눌러 작업자별 코드를 전달합니다

### 작업자 기기

1. 앱 실행 → **작업자 기기예요**
2. 관리자가 보내준 코드(`HENNY1:...`)를 붙여넣고 **연결하기**
3. 알림 권한 허용 → 끝

그다음부터 작업자는 앱을 켜면 **오늘 목록**만 봅니다. 항목을 한 번 누르면 완료입니다.

## 3. 데이터 저장소 고르기

서버를 따로 두지 않고, 작은 JSON 문서를 주고받는 방식입니다.

- **계획 문서 1개** — 관리자가 쓰고 작업자들이 읽음 (작업자 목록, 정기 작업, 임시 작업, 알림 시각)
- **기록 문서 (작업자당 1개)** — 그 작업자가 쓰고 관리자가 읽음 (날짜별 체크 기록)

쓰는 쪽과 읽는 쪽이 문서별로 나뉘어 있어 서로 덮어쓸 일이 없습니다.

### 지원하는 저장소

**① 구글 Firebase 실시간 데이터베이스 (권장, 기본값)**

구글 서비스이고 무료이며, **자료가 내 구글 계정 안에** 남습니다. 새로 가입할 것도 없습니다.

1. <https://console.firebase.google.com> 에 구글 계정으로 로그인
2. **프로젝트 만들기** → 이름 아무거나 (예: `henny`) → 애널리틱스는 **사용 안 함** → 만들기
3. 왼쪽 메뉴 **빌드 → Realtime Database** → **데이터베이스 만들기**
4. 위치는 **싱가포르(asia-southeast1)** 를 고르면 한국에서 빠릅니다 → 보안 규칙은 **잠금 모드**로 시작
5. **규칙** 탭에서 아래로 바꾸고 게시:

   ```json
   {
     "rules": {
       "henny": {
         "$family": {
           ".read": true,
           ".write": true
         }
       }
     }
   }
   ```

6. **데이터** 탭 맨 위의 주소를 복사 (`https://…-default-rtdb.asia-southeast1.firebasedatabase.app`)
7. 관리자 기기 설정에 붙여넣고 **연결하기**. 비밀키 칸은 **비워두면 됩니다.**

> **이 규칙이 안전한 이유:** 앱이 자료를 `henny/<무작위 32자>/…` 아래에 넣습니다.
> 이 무작위 값은 연결 코드로만 전달되고, 규칙상 `henny` 자체는 읽을 수 없어서
> 목록을 훑어볼 수도 없습니다. 즉 **연결 코드를 받은 사람만** 우리 팀 자료에 닿습니다.
> 더 엄격하게 하려면 Firebase 비밀키를 발급받아 규칙을 모두 `false` 로 잠그고
> 비밀키 칸을 채우면 됩니다.

무료 Spark 요금제는 저장 1GB, 월 다운로드 10GB입니다. 이 앱이 쓰는 양은 그 1000분의 1도 안 됩니다.

**② JSONBin.io**

작은 서비스지만 설정이 제일 단순합니다. 가입 후 **X-MASTER-KEY** 를 복사해
관리자 기기 설정에 붙여넣고 **저장 공간 만들기** 를 누르면 문서가 자동 생성됩니다.
무료 한도는 월 10,000회 호출입니다.

> ⚠️ 연결 코드 안에는 이 Master Key가 들어갑니다. 즉 **작업자 기기에도 같은 키가 저장됩니다.**
> 이 앱 전용 계정을 따로 만들어 쓰시길 권합니다.

**③ 직접 주소 (가입/키 없음)**

`GET`으로 읽고 `PUT`(또는 `POST`)으로 덮어쓸 수 있는 JSON 주소면 무엇이든 됩니다.
[jsonblob.com](https://jsonblob.com), [npoint.io](https://npoint.io) 등.
설정 탭에서 계획 문서 주소와 작업자별 기록 주소를 직접 넣습니다.
**인증이 없으므로 주소를 아는 사람은 누구나 읽고 쓸 수 있습니다.**

### 검토했지만 쓰지 않은 것

| 서비스 | 결론 |
|---|---|
| **dpaste** | ❌ 만든 붙여넣기를 **수정할 수 없습니다.** 체크할 때마다 새 URL이 생기고, 상대는 어느 게 최신인지 알 방법이 없습니다. 만료도 있습니다. |
| **Pastebin** | ⚠️ 수정 = 삭제 후 재생성이라 URL이 바뀝니다. 개발자 키 + 사용자 키가 따로 필요하고 무료 API 호출 한도가 빡빡합니다. |
| **네이버** | ❌ 네이버에는 이런 용도의 개인용 JSON 저장 서비스가 없습니다. 네이버 클라우드 플랫폼 Object Storage는 기업용이라 서명 요청이 필요하고 유료입니다. |
| **구글 드라이브 / 스프레드시트 API** | ⚠️ OAuth 로그인 흐름이 필요해 앱이 무거워지고 설정이 훨씬 복잡합니다. Firebase가 같은 구글이면서 훨씬 간단합니다. |

**③ 안 씀**

인터넷을 아예 쓰지 않고 그 폰에만 저장합니다. 작업자 혼자 쓰는 용도로는 이것만으로도 충분합니다.

## 3.5 동기화가 도는 방식

거의 실시간으로 맞되, 무료 저장소 한도를 낭비하지 않는 것이 목표입니다.

| 언제 | 무엇을 하나 |
|---|---|
| 앱을 열 때 | 곧바로 전체 동기화 |
| 화면이 켜져 있는 동안 | **15초마다 변경 여부만 확인**, 달라졌을 때만 전체를 받음 |
| 체크했을 때 | 2초 모았다가 업로드 (연타를 한 번으로 묶음) |
| 화면에서 나갈 때 | 확인 루프 중단 + 미뤄둔 업로드 마무리 |
| 알람이 울릴 때 | 알림을 띄우기 전에 최신 계획을 받아옴 |
| 새로고침 버튼 | 작업자·관리자 화면 모두 상단에 있음 |

**핵심은 "변경 여부만 확인"입니다.** Firebase 실시간 데이터베이스는 문서 안의 값 하나만
따로 읽을 수 있어서, 15초마다 `updatedAt` 숫자 하나(수십 바이트)만 받아 봅니다.
로컬보다 크면 그때 전체를 내려받습니다. 그래서 짧은 주기로 돌려도 거의 공짜입니다.

값 하나만 읽는 기능이 없는 백엔드(JSONBin, 직접 주소)는 문서를 통째로 받아야 하므로
확인 주기를 **60초**로 늘려 잡습니다.

불필요한 업로드도 막았습니다. 원격의 `updatedAt` 이 내 것과 같으면 올릴 것이 없다고 보고
건너뜁니다. 예전에는 동기화할 때마다 무조건 다시 올렸습니다.

화면이 꺼지면 루프가 멈추므로 배터리와 데이터를 백그라운드에서 축내지 않습니다.

## 4. 알림이 동작하는 방식

작업자가 앱을 아예 안 여는 게 가장 큰 문제라, 알림을 세 종류로 나눴습니다.

1. **하루 점검 알림** — 관리자가 시각을 정합니다. 기본값은
   - 아침 7:30 "오늘 할 일을 확인해요" (남은 게 없어도 알림)
   - 오후 4:00 "지금 하나만 시작해볼까?" (남은 게 있을 때만)
   - 저녁 8:00 "자기 전 마지막 점검!" (남은 게 있을 때만)
2. **마감 알림** — 할 일에 마감 시각을 넣으면 기본 1시간 전에 (30분/1시간/2시간 선택 가능)
3. **관리자 요약 알림** — 저녁 8:30에 "김민준 4/5  야간조 3/3" 형태로 하루 결과를 관리자 기기에 한 번

알람은 "다음에 울릴 하나"만 예약해 두고, 울릴 때마다 그다음을 다시 예약합니다.
재부팅·앱 업데이트·시간대 변경 뒤에도 자동으로 다시 걸립니다.

### 알림이 안 울린다면

앱 안에서 먼저:

- 설정 탭 → **알림 켜기** 로 권한 확인
- 설정 탭 → **알람 권한 열기** 에서 '알람 및 리마인더' 허용 (안드로이드 12 이상)

**삼성 갤럭시는 여기까지만 해서는 부족합니다.** One UI의 절전 기능이 오래 안 쓴 앱을
잠재워서 알람을 통째로 건너뛰게 만듭니다. 작업자 기기은 하루에 몇 번만 앱을 열기 때문에
바로 이 '안 쓰는 앱' 취급을 받습니다. 아래 두 가지를 꼭 해주세요.

1. **이 앱을 절전에서 제외**
   설정 → 앱 → **헨니 체크** → 배터리 → **제한 없음** 선택
2. **미사용 앱 절전 끄기**
   설정 → 배터리 → 백그라운드 사용 제한 → **미사용 앱을 절전 상태로 전환** 끄기

> One UI 버전에 따라 메뉴 이름이 조금씩 다릅니다.
> "디바이스 케어 → 배터리 → 앱 절전 관리 → 절전 제외 앱" 에 있는 기종도 있습니다.
> 어느 쪽이든 **헨니 체크가 '제한 없음' 또는 '절전 제외'** 로 되어 있으면 됩니다.

샤오미는 설정 → 앱 → 앱 관리 → 헨니 체크 → 배터리 절약 → **제한 없음**,
그리고 자동 시작(자동 실행) 허용까지 켜야 합니다.

## 5. 매일 쓰는 법

작업자 이름을 잘못 넣었거나 작업자를 지우려면 설정 탭의 작업자 목록에서 이름을 눌러 수정하고,
**삭제**로 지웁니다. (지금까지 쌓인 기록 문서는 남습니다.)

**마일리지** — 작업마다 배점이 붙습니다. 기본 **100P**이고 추가·수정할 때 바꿀 수 있습니다
(50 / 100 / 200 / 500 빠른 선택도 있습니다). 작업자 화면에는 오늘 모은 마일리지, 이번 주 마일리지,
지금까지 쌓은 누적 마일리지가 나오고, 점검 알림에도 남은 작업의 배점이 함께 표시됩니다.

> 배점은 **체크한 시점의 값으로 기록에 박힙니다.** 나중에 관리자가 배점을 바꿔도 이미 쌓인
> 마일리지는 흔들리지 않습니다.

**정기 작업** — 관리자 기기 → 작업 탭 → 작업자 선택 → 작업 추가.
요일(기본 평일)과 마감 시각을 정합니다. 예: 일일 점검표 작성, 재고 확인, 장비 점검.
3~5개 정도가 적당합니다. 잠시 쉬게 하려면 지우지 말고 **사용 중** 스위치만 끄면 통계가 보존됩니다.

**하루짜리 임시 작업** — 관리자 기기 → 오늘 탭 → 작업자 카드의 **임시 작업 배정**.
"오늘은 창고 재고 확인" 같은 걸 넣으면 작업자 목록 맨 위에 **임시 작업** 배지로 뜹니다.

**통계** — 관리자 기기 통계 탭에서 주간 막대그래프와 월간 달력, 달성률·해낸 일 개수·완벽한 날 수를 봅니다.
작업자도 자기 화면 아래에서 이번 주 기록과 연속 달성 일수를 봅니다.

> 작업자가 앱을 한 번도 안 연 날도 "해야 했던 개수"를 통계 분모에 넣습니다.
> 안 한 날이 안 한 날로 보이게 하려는 의도입니다.

## 5.5 업데이트할 때 데이터가 날아가지 않게

지금까지 앱을 새로 받을 때마다 지우고 다시 깔아야 했고 기록도 사라졌습니다. 원인은 두 가지였습니다.

**① 빌드마다 서명이 달랐다**
GitHub Secrets 에 업로드 키를 넣기 전에는 CI 가 **일회용 키**로 서명했습니다.
안드로이드는 서명이 다른 앱을 같은 앱으로 보지 않아서 덮어 설치를 거부합니다.
그래서 지우고 다시 깔 수밖에 없었고, 앱을 지우면 그 기기의 자료도 함께 사라집니다.

→ **업로드 키를 등록한 뒤로는 해결됐습니다.** 이제 모든 빌드가 같은 키로 서명되므로
**덮어 설치가 되고 자료가 유지됩니다.**

**② 저장 형식이 바뀌었다**
개발 중에 필드 이름이 바뀌면(예: `childId` → `workerId`) 예전 파일을 읽지 못합니다.
예전에는 이때 조용히 빈 상태로 시작했습니다. 지금은 못 읽은 파일을 `.broken` 으로 남겨 두고,
설정 화면에 그 사실을 알려 줍니다. **팀 저장소를 쓰고 있으면 잠시 뒤 원격에서 다시 내려받습니다.**

### 그래서 권하는 구성

- **팀 저장소(Firebase)를 반드시 켜세요.** 기기가 비어도 자료는 클라우드에 있습니다.
  앱을 지웠다 깔아도 코드만 넣으면 그대로 돌아옵니다.
- **관리자 기기는 복구 코드를 저장해 두세요.**
  설정 → 이 기기 → **복구 코드 보기** → 복사해서 메모나 비밀번호 관리자에 보관.
  이 코드에는 저장소 접속 정보와 모든 문서 주소가 들어 있습니다.

  > ⚠️ 이게 없으면 관리자 기기를 재설치할 때 **새 저장 경로를 만들어 버려서
  > 그동안 쌓인 자료가 고아가 됩니다.** 작업자 기기는 관리자에게 연결 코드를 다시 받으면 되지만,
  > 관리자 기기는 이 코드가 유일한 복구 수단입니다.

- 작업자 기기는 관리자 설정 탭에서 **연결 코드**를 다시 받아 넣으면 기록이 복구됩니다.

### 복구하는 법

1. 앱 실행 → 첫 화면에서 **쓰던 기기 복구 (코드 있음)**
2. 저장해 둔 복구 코드(관리자) 또는 연결 코드(작업자)를 붙여넣기
3. 자동으로 팀 저장소에서 자료를 내려받습니다

설정 화면 아래쪽에 **앱 버전**이 표시되니, 업데이트가 실제로 반영됐는지 눈으로 확인할 수 있습니다.

### 진짜 해결책은 스토어 배포

위 방법으로 자료는 지킬 수 있지만, **파일을 받아서 설치하는 수고 자체는 남습니다.**
Play 내부 테스트에 올리면 그 수고가 사라집니다 — 새 버전을 올리면 각자 폰에서
**자동으로 업데이트**됩니다. 받을 것도, 누를 것도 없습니다.
업로드 키는 이미 준비됐으니 [PLAY_STORE.md](PLAY_STORE.md) 2단계부터 진행하시면 됩니다.

## 6. 서명키에 대한 안내

업로드 키는 **저장소에 두지 않습니다.** GitHub Secrets 에 넣으면 CI 가 꺼내 씁니다.

- `KEYSTORE_BASE64` — 키스토어 파일을 base64 로 인코딩한 값
- `KEYSTORE_STORE_PASSWORD`, `KEYSTORE_KEY_ALIAS`, `KEYSTORE_KEY_PASSWORD`

**컴퓨터가 없어도 브라우저에서 만들 수 있습니다.**
왜 필요한지와 태블릿에서 만드는 법은
[PLAY_STORE.md 1단계](PLAY_STORE.md#1-업로드-키-만들기-필수-제일-먼저)에 정리해 두었습니다.

> ⚠️ 초기 커밋에 들어 있던 `keystore/henny-family.jks`(비밀번호 `hennyfamily`)는 삭제했습니다.
> 공개 저장소에 노출됐던 키라 **다시 쓰면 안 됩니다.** git 기록에는 남아 있습니다.

## 7. 기술 메모

- Kotlin + Jetpack Compose (Material 3), minSdk 26(안드로이드 8.0), targetSdk 35
- 데이터베이스 없음 — 작은 JSON 파일 3개로 저장하고 그대로 원격에 올립니다
- 네트워크 라이브러리 없음 — `HttpURLConnection` 하나
- WorkManager 없음 — 화면이 켜져 있는 동안만 도는 가벼운 확인 루프를 쓴다
- R8 축소 + 리소스 축소 적용 — 릴리스 APK 약 1MB
- compileSdk / targetSdk 36 (Android 16), Play용 AAB와 사이드로딩용 APK를 함께 빌드

빌드 전 점검:

```bash
python3 tools/sanity_check.py
```

안드로이드 SDK 없이 손보는 경우가 있어, 컴파일까지 가지 않고도 잡히는 실수 두 가지를
미리 검사합니다 — 컴포저블의 후행 람다가 `modifier` 에 붙는 문제, 그리고 중괄호 짝이
어긋난 파일. CI 에서도 빌드 앞단에 돌립니다.

로컬 빌드:

```bash
./gradlew assembleRelease   # app/build/outputs/apk/release/app-release.apk
```

Android SDK가 설치되어 있고 `local.properties`에 `sdk.dir`이 잡혀 있어야 합니다.

## 배포 흐름

```
git push (main)  ->  Actions: 검사 -> Pages 배포  ->  가족이 앱을 여는 순간 최신
```

APK 는 껍데기라 거의 바뀌지 않습니다. 화면과 규칙은 `web/` 에 있으므로
하루에 몇 번을 고쳐도 다시 설치할 필요가 없습니다.

### 처음 한 번만 (저장소 설정 2가지)

1. **Settings → Pages → Source** 를 **GitHub Actions** 로. *(완료)*
2. **Settings → General → Default branch** 를 **main** 으로.

2번을 빠뜨리면 배포가 **로그 한 줄 없이 몇 초 만에 실패**합니다. Pages 가 쓰는
`github-pages` 환경이 기본 브랜치에서 온 배포만 받기 때문입니다. 실패 화면에
아무 단서가 없어서 원인을 찾기 어려운 부분이라 적어 둡니다.

두 가지가 맞으면 주소는 이렇습니다.

- 앱: `https://nohkwangsun.github.io/henny/`
- 개인정보처리방침: `https://nohkwangsun.github.io/henny/privacy.html`
