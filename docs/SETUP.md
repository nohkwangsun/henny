# 저장할 곳 만들기

기기끼리 자료를 주고받으려면 저장할 곳이 하나 필요합니다.
**구글 Firebase 실시간 데이터베이스**를 씁니다. 무료이고, 구글 계정만 있으면 되고,
자료가 내 구글 계정 안에 남습니다.

앱 안에서도 같은 순서를 화면에 띄워 주므로, 이 문서를 안 봐도 따라갈 수 있습니다.

---

## 만드는 순서 (5분)

1. <https://console.firebase.google.com> 에 구글 계정으로 로그인
2. **프로젝트 만들기** → 이름은 아무거나 (예: `henny`) → 애널리틱스는 **사용 안 함** → 만들기
3. 왼쪽 메뉴 **빌드 → Realtime Database** → **데이터베이스 만들기**
4. 위치는 **싱가포르(asia-southeast1)** 가 한국에서 빠릅니다
5. 보안 규칙은 **테스트 모드로 시작**을 고릅니다
6. **데이터** 탭 맨 위의 주소를 복사합니다

   ```
   https://…-default-rtdb.asia-southeast1.firebasedatabase.app
   ```

7. 관리자 기기 설정 화면에 붙여넣고 **연결하고 시작**. 비밀키 칸은 **비워두면 됩니다.**

주소 뒤에 경로나 물음표가 붙어 복사돼도 앱이 알아서 잘라냅니다.

---

## 30일 뒤에 해야 할 일

테스트 모드는 **30일 뒤 규칙이 잠기게** 되어 있습니다. 그전에 한 번만 바꿔 주세요.

Realtime Database → **규칙** 탭 → 아래를 붙여넣고 **게시**:

```json
{
  "rules": {
    "henny": {
      "$team": {
        ".read": true,
        ".write": true
      }
    }
  }
}
```

메일로 잠긴다는 안내가 오므로 놓치기 어렵습니다. 잠긴 뒤에 바꿔도 자료는 그대로입니다.

### 이 규칙이 안전한 이유

앱은 자료를 `henny/<무작위 32자>/…` 아래에 넣습니다.

- 그 무작위 값은 **연결 코드로만** 전달됩니다
- 규칙상 `henny` 자체는 읽을 수 없어서 **목록을 훑어볼 수 없습니다**

그래서 이 규칙으로도 **연결 코드를 받은 사람만** 우리 팀 자료에 닿습니다.

더 엄격하게 하려면 Firebase 비밀키를 발급받아 규칙을 모두 `false` 로 잠그고,
앱 설정의 비밀키 칸을 채우면 됩니다.

---

## 비용

무료 Spark 요금제는 저장 1GB, 월 다운로드 10GB입니다.
이 앱이 쓰는 양은 그 1000분의 1도 안 됩니다. 카드 등록도 필요 없습니다.

15초마다 확인하지만 그때 받는 것은 `updatedAt` 숫자 하나(수십 바이트)뿐입니다.
자세한 규칙은 [ARCHITECTURE.md](ARCHITECTURE.md#동기화)에 있습니다.

---

## 저장할 곳 없이 쓰기

첫 설정에서 **건너뛰기**를 고르면 그 기기 안에만 저장합니다.
혼자 쓰거나 먼저 둘러보고 싶을 때 씁니다. 나중에 설정 탭에서 연결하면
그때부터 다른 기기와 이어집니다.

---

## 다른 선택지

앱은 아래도 지원합니다. 설정 탭에서 바꿀 수 있습니다.

**JSONBin.io** — 설정이 제일 단순합니다. 가입 후 **X-MASTER-KEY** 를 복사해 넣고
저장 공간 만들기를 누르면 됩니다. 무료 한도는 월 10,000회 호출.

> ⚠️ 연결 코드 안에 이 Master Key 가 들어갑니다. 즉 작업자 기기에도 같은 키가 저장됩니다.
> 이 앱 전용 계정을 따로 만들어 쓰세요.

**직접 주소** — `GET` 으로 읽고 `PUT`(또는 `POST`)으로 덮어쓸 수 있는 JSON 주소면
무엇이든 됩니다. [jsonblob.com](https://jsonblob.com), [npoint.io](https://npoint.io) 등.
**인증이 없으므로 주소를 아는 사람은 누구나 읽고 쓸 수 있습니다.**

## 검토했지만 쓰지 않은 것

| 서비스 | 결론 |
|---|---|
| **dpaste** | ❌ 만든 붙여넣기를 **수정할 수 없습니다.** 체크할 때마다 새 주소가 생기고, 상대는 어느 게 최신인지 알 방법이 없습니다. 만료도 있습니다. |
| **Pastebin** | ⚠️ 수정이 곧 삭제 후 재생성이라 주소가 바뀝니다. 개발자 키와 사용자 키가 따로 필요하고 무료 호출 한도가 빡빡합니다. |
| **네이버** | ❌ 이런 용도의 개인용 JSON 저장 서비스가 없습니다. 네이버 클라우드 플랫폼 Object Storage 는 기업용이라 서명 요청이 필요하고 유료입니다. |
| **구글 드라이브 / 스프레드시트 API** | ⚠️ OAuth 로그인 흐름이 필요해 앱이 무거워지고 설정이 훨씬 복잡합니다. Firebase 가 같은 구글이면서 훨씬 간단합니다. |
