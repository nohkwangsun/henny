# 서버 개발자를 위한 모바일 기초

이 프로젝트를 읽기 전에 알아 두면 좋은 것만 모았습니다. 안드로이드 전반을
다루지 않고, **서버 개발과 전제가 다른 지점**에만 집중합니다.

읽는 분이 이미 아는 것(HTTP, JSON, 동시성, 빌드 도구, CI)은 설명하지 않고,
"왜 이렇게 되어 있나"만 적습니다.

---

## 1. 가장 큰 차이: 프로세스가 언제든 죽는다

서버 프로세스는 내가 죽이기 전까지 삽니다. 폰은 반대입니다.

사용자가 홈 버튼을 누르고 다른 앱 몇 개를 열면, OS 가 메모리를 회수하려고
내 프로세스를 **조용히 죽입니다.** 예고도 없고, 셧다운 훅도 보장되지 않고,
로그도 안 남습니다. 그리고 사용자가 앱을 다시 열면 새 프로세스가 뜹니다.

여기서 파생되는 규칙:

| 서버에서 통하던 것 | 폰에서는 |
|---|---|
| 메모리에 캐시해 두면 됨 | 언제 사라질지 모름. 남길 건 즉시 디스크에 |
| 스케줄러 스레드로 정각 작업 | 프로세스가 없을 수 있음. OS 에 예약을 맡겨야 함 |
| graceful shutdown 훅 | 없다고 봐야 함 |
| 싱글턴은 앱 생명주기 내내 유지 | 프로세스 생명주기. 하루에도 여러 번 새로 만들어짐 |

> 이 앱에서: 알림 일정을 메모리에 들고 있지 않고 `ScheduleStore` 가 즉시
> 파일에 씁니다. 알람도 앱이 기다리는 게 아니라 OS 에 맡깁니다.

---

## 2. Activity 에는 main() 이 없다

`MainActivity` 는 우리가 `new` 해서 실행하는 객체가 아닙니다. **OS 가 만들고
OS 가 없앱니다.** 우리는 정해진 시점에 끼어들 뿐입니다. 서블릿 컨테이너가
서블릿을 다루는 방식에 가깝습니다.

주요 시점만:

```
onCreate()   화면 객체가 처음 만들어짐. 앱 시작과 다름
onStart()    사용자에게 보이기 시작. 앱을 나갔다 올 때마다 다시 불림
onResume()   포커스를 받음
  ... 사용 중 ...
onPause()    가려지기 시작
onStop()     안 보임
onDestroy()  없어짐. 불린다는 보장 없음 (프로세스가 그냥 죽을 수 있음)
```

**중요한 함정:** 화면을 회전하면 기본 동작은 `onDestroy()` → `onCreate()` 입니다.
즉 화면 객체가 통째로 새로 만들어집니다. 상태를 필드에 들고 있었다면 날아갑니다.

> 이 앱에서: 회전 때마다 WebView 가 새로 로드되면 사용자가 보던 화면이 날아가므로,
> `AndroidManifest.xml` 의 `configChanges` 로 그 재생성을 끕니다.

---

## 3. AlarmManager 는 cron 이 아니다

"매일 7시 30분에 알림"을 서버라면 cron 이나 스케줄러로 끝냅니다. 폰에서는
프로세스가 그때 없을 수 있으므로, **OS 에 예약을 맡깁니다.**

```
앱: "OS야, 이 시각에 나를 깨워 줘"   ← AlarmManager.setExact...()
                (프로세스가 죽어도 예약은 OS 가 들고 있음)
OS: (그 시각에) 앱 프로세스를 잠깐 띄워서 BroadcastReceiver 를 부름
```

그런데 OS 는 이 약속을 **정확히 지킬 의무가 없습니다.** 배터리 때문입니다.

- **Doze**: 화면이 꺼지고 기기가 가만히 있으면 절전 모드로 들어가, 예약된 알람을
  몇 분~몇십 분씩 모아 뒀다가 한꺼번에 처리합니다.
- **제조사 절전**: 삼성 One UI, 샤오미 MIUI 등은 더 공격적입니다. 자주 안 쓰는
  앱을 아예 재워서 알람을 건너뛰기도 합니다. **표준 API 로는 손쓸 수 없고**
  사용자가 설정에서 예외로 지정해야 합니다.
- **정확 알람 권한**: 안드로이드 12부터 "정확히 그 시각에" 울리려면 별도 권한
  (`SCHEDULE_EXACT_ALARM`)이 필요합니다. 없으면 몇 분씩 밀립니다.
- **재부팅하면 예약이 전부 사라집니다.** OS 가 영구 저장하지 않습니다.
  앱 업데이트도 마찬가지입니다. 그래서 `BootReceiver` 로 다시 겁니다.

> 이 앱에서: `AlarmScheduler` 가 "다음 한 개"만 예약하고, 울릴 때마다 다음 것을
> 다시 겁니다. 재부팅·업데이트·시간대 변경 때도 다시 겁니다.

---

## 4. 권한은 선언과 요청이 따로다

`AndroidManifest.xml` 에 권한을 적는 것은 **"쓰겠다는 선언"**일 뿐입니다.
민감한 권한은 실행 중에 사용자에게 따로 물어야 하고, 거절당할 수 있습니다.

두 종류:

- **설치 시 자동 부여**: `INTERNET`, `VIBRATE` 등. 물어보지 않습니다.
- **실행 중 요청**: `POST_NOTIFICATIONS`(안드13+), 카메라, 위치 등.

**가장 성가신 특성:** 권한이 없을 때 대부분의 API 는 **예외를 던지지 않고
조용히 아무 일도 안 합니다.** 알림이 그렇습니다. 로그도 안 남습니다.
그래서 "알림이 안 오는데 이유를 모르겠다"가 흔한 상황이고, 앱이 미리 확인해서
사용자에게 알려 줘야 합니다.

> 이 앱에서: `Notifications.canPost()` 로 먼저 확인하고, 설정 화면에
> "알림이 꺼져 있어 아무것도 울리지 않습니다"를 띄웁니다.

## 5. APK 서명 = 앱의 신원

이게 서버 개발에 대응물이 없어서 처음에 잘 놓칩니다.

안드로이드에서 **앱의 정체성은 `applicationId` + 서명 키**입니다.
같은 `com.henny.checklist` 라도 **서명이 다르면 OS 는 완전히 다른 앱으로 봅니다.**

결과:

- 서명이 다른 APK 는 **덮어 설치가 거부됩니다.** ("앱이 설치되지 않았습니다")
- 지우고 새로 깔면 설치는 되지만, **그 앱이 쓰던 저장 공간이 통째로 사라집니다.**
  우리 경우 `localStorage` 가 여기 포함됩니다.

> 이 프로젝트에서 실제로 겪은 문제입니다. 업로드 키를 등록하기 전에는 CI 가
> 빌드마다 일회용 키를 새로 만들어 서명했고, 그래서 매번 지우고 새로 깔아야 했고
> 그때마다 자료가 날아갔습니다. 지금은 GitHub Secrets 의 고정 키로 서명합니다.

키를 잃어버리면? 스토어에 올린 뒤라면 구글에 업로드 키 재설정을 요청할 수
있습니다. 사이드로딩만 한다면 방법이 없습니다 — 사용자가 지우고 새로 깔아야 합니다.

## 6. 버전은 두 개다

```kotlin
versionCode = 37      // 정수. 스토어가 "더 새 버전인가"를 이것만 보고 판단
versionName = "1.0.37" // 문자열. 사람이 읽는 용도. 아무 의미 없음
```

`versionCode` 는 반드시 단조 증가해야 합니다. 한 번 올린 값보다 낮으면 스토어가
거부합니다. 이 프로젝트는 CI 실행 번호를 그대로 씁니다.

---

## 7. targetSdk 는 숫자가 아니라 동작 계약

```kotlin
minSdk = 26     // 이 버전 미만 기기에는 설치 안 됨
targetSdk = 36  // "이 버전까지 맞춰 만들었다"는 선언
compileSdk = 36 // 컴파일에 쓸 SDK. 기기 조건과 무관
```

`targetSdk` 를 올리면 **앱 동작이 실제로 바뀝니다.** OS 가 이 값을 보고 어떤
규칙을 적용할지 정하기 때문입니다. 예:

- `targetSdk >= 33`: 알림에 사용자 동의가 필요해짐
- `targetSdk >= 35`: 화면을 시스템 막대 뒤까지 그림 (edge-to-edge)

> 이 앱에서 겪은 것: `targetSdk` 35 때문에 화면 맨 윗줄이 상태바 시계와 겹쳤습니다.
> 코드는 그대로였고 숫자만 올라갔는데 화면이 깨진 겁니다.

구글 플레이가 매년 하한을 올리므로 계속 따라가야 합니다.

## 8. 스토어 배포의 제약 — 여기가 핵심

**"업데이트 없이 신기능이 들어오는" 앱들의 실체가 여기 있습니다.**

구글 플레이와 애플 양쪽 다 **실행 가능한 네이티브 코드를 내려받아 실행하는 것을
금지합니다.** 보안 검수를 우회할 수 있기 때문입니다.

그래서 무선으로 바꿀 수 있는 것과 없는 것이 갈립니다:

| 무선으로 바꿀 수 있음 | 스토어 업데이트 필요 |
|---|---|
| 웹뷰가 여는 웹 콘텐츠 | 네이티브 코드 (Kotlin/Java/Swift) |
| JS 번들 (React Native 등) | 새 권한 |
| 서버가 내려주는 화면 정의 (SDUI) | 매니페스트 변경 |
| 기능 플래그로 켜고 끄기 | 네이티브 라이브러리 추가 |
| 서버 API 응답 | targetSdk 변경 |

**인스타그램·에어비앤비도 이 선은 똑같습니다.** 그들이 항상 무선으로 되는 것처럼
보이는 이유는 두 가지입니다:

1. **기능 플래그** — 새 기능 코드를 미리 앱에 넣어 배포해 두고, 서버에서 스위치만
   켭니다. 사용자 눈에는 "업데이트 없이 생긴" 걸로 보이지만 이미 설치돼 있던
   겁니다. 그래서 같은 버전인데 사람마다 화면이 다른 일이 생깁니다.
2. **자동 업데이트** — 안드로이드는 기본이 자동 업데이트라, 네이티브 변경이
   있어도 사용자가 모르는 사이 끝납니다.

> 이 프로젝트가 웹뷰 구조를 택한 이유가 이것입니다. 바뀌는 것 대부분을 웹 쪽에
> 두면 스토어와 무관해집니다. 자세한 경계는 `CODE-TOUR.md` 참고.

## 9. 하이브리드 앱과 JS 브리지

WebView 는 **앱 안에 박아 넣은 크롬**입니다. 웹 페이지를 앱 화면으로 씁니다.

웹에서 네이티브 기능(알람, 카메라)을 쓰려면 다리가 필요합니다:

```kotlin
webView.addJavascriptInterface(Bridge(), "HennyShell")
```

이러면 웹 쪽에서 `window.HennyShell.setSchedule(...)` 로 부를 수 있습니다.
`@JavascriptInterface` 가 붙은 메서드만 건너갑니다.

**두 가지 함정:**

1. **스레드**: 브리지 메서드는 UI 스레드가 **아닌** WebView 의 별도 스레드에서
   불립니다. 화면을 건드리려면 `runOnUiThread` 로 넘겨야 합니다.
2. **보안**: 브리지는 그 WebView 에 로드된 **모든** 페이지에 열립니다. 남의
   페이지를 열 수 있게 만들면 그 페이지도 우리 함수를 부를 수 있습니다.
   이 앱은 우리 주소 하나만 열어서 안전합니다.

## 10. 화면과 키보드

서버 개발에서 안 겪는 것들:

- **안전 영역(safe area)**: 노치, 펀치홀, 둥근 모서리, 제스처 바. 화면 가장자리
  일부는 실제로 쓸 수 없습니다. 값이 기기마다 다르고 회전하면 바뀌므로 상수로
  박을 수 없고, OS 가 알려주는 걸 받아야 합니다 (`WindowInsets`).

- **키보드가 화면을 가린다**: 이게 특히 성가십니다. 안드로이드는 키보드가 올라와도
  **레이아웃 뷰포트(`100vh`)가 줄지 않습니다.** CSS 로 "화면 한가운데"에 둔 요소는
  키보드 뒤에 그대로 남습니다.

  실제로 보이는 영역은 `window.visualViewport` 로만 알 수 있습니다:

  ```
  layout viewport   실제 보이는 영역(visual viewport)
  ┌──────────┐      ┌──────────┐
  │          │      │          │  ← visualViewport.height
  │  모달     │      │──────────│
  │          │      │  키보드   │  ← 여기 있는 건 못 누름
  └──────────┘      └──────────┘
     100vh 그대로
  ```

  > 이 앱에서 겪은 것: 저장 버튼이 키보드 뒤에 남아 스크롤로도 닿을 수 없었습니다.
  > `visualViewport` 로 실제 높이를 재서 CSS 변수로 넘겨 고쳤습니다.

- **터치 목표**: 손가락은 마우스보다 훨씬 뭉툭합니다. 최소 44~48px 이 권장치이고,
  그보다 작으면 옆 것이 눌립니다.

## 11. localStorage 는 DB 가 아니다

WebView 안의 웹앱이 자료를 담는 곳입니다.

- **문자열만** 담깁니다. 넣고 뺄 때마다 `JSON.stringify/parse`.
- **동기 API** 입니다. 읽기/쓰기가 메인 스레드를 잠깐 막습니다.
- **5~10MB** 로 작습니다. 넘으면 예외.
- 격리 단위가 **오리진**(스킴+호스트+포트)입니다.
- **앱을 지우면 같이 사라집니다.** 덮어 설치로는 안 사라집니다.

마지막 줄이 중요합니다. "업데이트하면 자료가 없어지나?"의 답이 여기 있습니다.
덮어 설치(같은 서명)면 남고, 지웠다 깔면(또는 서명이 다르면) 사라집니다.
